## Frozen duplicate / representative rules

Verified identical source SHA creates exact edges across sources/kinds/filenames.
Same filename alone is not exact identity. Reuse unchanged 64-bit DCT pHash;
face pHash uses persisted bbox without a new margin or detector. Missing face hash
stays MISSING, never global-as-face. Source SHA/decode/dimension errors retain rows
in isolated failed audit, not successful clusters.

The following are current Config SSOT defaults, frozen from requested legacy rules:

| Context | Near-edge conditions |
| --- | --- |
| Same-video temporal | index gap<=6 AND raw yaw/pitch Euclidean gap<=12° AND (global OR face Hamming<=14) |
| Same-video tight | raw angle gap<=8° AND (global OR face Hamming<=10), no temporal requirement |
| Supplemental stills | raw measured angle gap<=8° AND global Hamming<=10 AND face Hamming<=10 |
| Different videos / video-vs-still | Exact SHA only |
| Pose NOT_EVALUABLE | Exact SHA only; no invented angle |

No pose_bin/face_scale_bin equality gate. Union-Find clusters retain alternatives.
Representative/rank = best_score DESC, global_rank ASC, frame_id ASC. Human/identity
are not features. Full SHA256 of sorted member frame IDs identifies every cluster,
including UNIQUE; current validated universe provides generation context.

Max pairwise pose spread, one-video temporal min/max, max hash distances to
representative and edge types expose chaining. Near-edge clusters warn above
their largest applicable frozen angle bound; no invented split rule. Exact-only
clusters are not called near-edge chains. Evidence incident-row counts are not
disjoint classes; temporal/tight edges may overlap.

## Publication / STEP6 compatibility

--limit preserves full audit rows, marking unprocessed eligible rows
PARTIAL_NOT_ANALYZED with ERROR/unavailable role, never quality Reject. Partial
and failed outputs publish only under reports/audit/step5_dedup_v2_<id>.
Successful output is fully staged; prior files copied with manifest/hashes to bkup;
per-file atomic replaces, summary last. Caught replacement errors attempt rollback.
Process crash/rollback filesystem failure is not a multi-file transaction; summary
hashes detect inconsistent companions and archives support recovery.

dedup_role is authoritative. duplicate_status=unique/representative/duplicate and
duplicate_group are aliases. STEP6 default reads these and raw filename/named bbox,
so no copies or STEP6 code edit is needed for the structural bridge. STEP6's
eval-all-eligible still expects face_eligible; pose_bucket/pose_yaw refer to old
schema and report fallback/safety need next-STEP audit. Identity readiness is not
claimed. Normal runner stops after STEP5 for Chappy cluster/pose review.
